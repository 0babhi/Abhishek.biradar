Introducing Today's Project

What is Amazon VPC?

Amazon VPC is an isolated cloud environment where AWS services can be tested without being in the main network.

How I used Amazon VPC

In this project, I used Amazon VPC for VPC peering and network connectivity testing.

What I didn't expect

One thing I didn't expect was working with CloudWatch Logs Insights and queries.

Project duration

Approximately 60 minutes.

Multi-VPC Architecture

I created two VPCs with separate CIDR blocks, public subnets and EC2 instances. VPC Flow Logs were configured to capture network traffic, while VPC Peering was later used to establish private communication between the VPCs.

Implementation

Step 1 — Set up VPCs

Created two VPCs from scratch and configured their networking. The VPCs use unique CIDR blocks so their IP ranges do not overlap.

Step 2 — Launch EC2 instances

Launched EC2 instances in each subnet so connectivity could be tested between the instances.

Step 3 — Set up Logs

Configured VPC Flow Logs to track inbound and outbound network traffic and created a location for storing the records.

Step 4 — Set IAM permissions for Logs

Created the IAM policy and role required for VPC Flow Logs to write records to CloudWatch.

Connectivity Troubleshooting

Initial ping test

The first ping test between the EC2 instances did not receive replies. Security-group rules were adjusted to allow ICMP traffic for testing.

Public IP test

Ping using the other instance's public IPv4 address worked, showing that the instances could communicate across the public path.

Private IP test

The private-IP ping failed because the VPCs did not yet have a private route between them.

Solution — VPC Peering

Created a VPC Peering connection and updated both VPC route tables with the remote VPC CIDR. After this change, the EC2 instances could communicate using private IP addresses.

VPC Flow Logs

VPC Flow Logs provide information about IP traffic going to and from network interfaces in a VPC.

Important fields include:

versionaccount-idinterface-id srcaddrdstaddrsrcport dstportprotocol

CloudWatch Logs Insights

CloudWatch Logs Insights can analyze log data using queries to filter, process and combine records for troubleshooting and traffic analysis.

The project used a query focused on identifying the top data transfers by source and destination IP addresses.

IAM Configuration

An IAM policy was created to define the actions allowed, and an IAM role was created so VPC Flow Logs could access the required permissions and publish logs.

What I learned

This project gave me hands-on practice with VPC networking, EC2 connectivity, security groups, route tables, VPC Peering, VPC Flow Logs, IAM permissions and CloudWatch Logs Insights.

The key troubleshooting flow was: test connectivity → inspect routing → establish VPC Peering → update routes → verify private connectivity → analyze Flow Logs.
